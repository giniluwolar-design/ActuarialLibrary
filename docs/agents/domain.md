# Domain docs

This is a single-context repository. Read the root `CONTEXT.md` before work involving product or actuarial terminology. Read relevant system-wide decisions under `docs/adr/` when that directory exists.

If either location is absent, proceed without inventing content. Domain-modeling work creates glossary entries and ADRs only when terms and durable trade-offs are actually resolved.

Use the glossary’s canonical vocabulary in issue titles, specifications, code, tests and explanations. If a required concept is absent or conflicts with existing language, surface the gap for domain modeling.

If proposed work contradicts an existing ADR, identify the conflict explicitly and explain why reopening the decision may be warranted.
