# Roadmap and product context

## Current release: reserving triangles

Establish the complete local chain of input, controls, methods, selections, explanations and reusable outputs. Keep the computation independent of the interface. Treat transparent provenance and reduced preparation work as primary benefits; measure calculation speed instead of assuming it.

## Next: financial data adapters

Add EIOPA risk-free curves and specific DNB datasets as separate connectors after selecting their exact series, official sources, revision policies, terms and required transformations. Each adapter should expose typed data, units, valuation date, source URL, retrieval timestamp and content hash. Store source and transformed values separately. Do not hardcode an undocumented endpoint or claim an unimplemented feed already works.

## Then: MCP and chat

Expose validated library operations through a small MCP server: inspect inputs, build triangles, calculate named methods, compare assumptions and retrieve explanations. Keep all actuarial results deterministic and generated by the library. Chat should not invent priors, choose final reserves or silently alter analysis scope. Large raw data stays in the analysis environment; the conversational layer requests scoped results and provenance.

## Revisit the spreadsheet workspace

The broader product problem is a fragmented actuarial chain across spreadsheets, scripts, controls and report preparation. After the first modules work, assess whether a common visual modelling workspace reduces the need for separate tools. Measure preparation time, review effort, explanation quality, total run time and adoption by business specialists. A fast spreadsheet-style interface may become a shared front end for these library functions rather than replacing their tested calculation logic.

## Explicit later features

Mack uncertainty, bootstrap simulation, discounting, recovery and reinsurance layers, contractual deductible allocation, full configurable Excel export, user access controls and formal approvals are later decisions. Public hosting and GitHub publication are not performed automatically. The existing cash-flow prototype remains separate until an intentional integration decision.
